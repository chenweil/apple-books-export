# ADR 0008: AppKit 作为语音生成的第二个用户入口

- 状态：已接受
- 日期：2026-09-30
- 关联：[`ADR 0006`](0006-appkit-initial-capability-boundary.md)、[`ADR 0007`](0007-annotation-speech-generation-boundary.md)
- 后续：[`ADR 0009`](0009-speech-export-target.md)（语音导出的目标目录）

## 背景

`ADR 0007` 确立了标注语音生成的供应商边界，并把**首版用户入口定为 Rust CLI**，同时写明
「未来 AppKit 消费同一 Rust 合同」。`ADR 0006` 记录了 AppKit 的首期能力边界，但它的
能力清单**完全没有提到语音** —— 无论在「AppKit 首期必须提供」还是「保留在 Rust
CLI/Skill 的能力」里。

结果是：语音不在 AppKit 里这件事，既没有被写成决策，也没有被写成例外。AppKit 的
首期能力边界文档读起来像是一份完整清单，而它漏掉了一整类能力。这不是 AppKit 的
缺陷，是一个文档缺口 —— 一个能让人以为「AppKit 有语音，只是我找不到」的缺口。

现在 AppKit 语音面板已经实现（PR #54 协议与凭证通道、#55 面板与播放），这个入口
需要自己的决策记录，而不是靠 `#54` / `#55` 的提交信息来说明。

## 决策

### AppKit 是语音的第二个用户入口，不是第二个实现

- AppKit 语音面板**不实现任何语音语义**。Annotation 内容选择、Voice Profile 解析、
  供应商调用、Cached Speech Clip 与 Exported Speech Clip 的生命周期，全部由 Rust 核心
  通过 machine JSON 拥有；AppKit 只消费 `speech voices` / `profile` / `generate` /
  `play` 的 receipt 与稳定错误码；
- AppKit **不缓存自己的副本**。它不保存生成的音频、不缓存目录、不复制 provider
  规则。面板显示的音频路径来自 CLI 已经校验过的结果；
- 这与 `ADR 0007` 「若由 CLI、AppKit 或其他入口分别维护文本选择、供应商参数、缓存
  和音频文件规则，会重新产生多套事实源」是同一条理由。

### 机器入口不播放，人类入口播放

`ADR 0007` 写明「人类 `speech play` 使用 macOS 系统播放器播放已有音频。Machine JSON
播放入口只返回状态和路径，不产生声音」。

因此 AppKit 走人类入口这一侧：`speech play --json` 返回**已校验的**绝对路径，
AppKit 用 AVFoundation 播放该路径。AppKit 不重新解析音频位置 —— CLI 已经完成校验，
在这里再解析一次就等于引入了第二个决定「某个 clip 是哪段音频」的地方。

面板**断言**这个假设而不是相信它：若某次回执声称 `played == true`，面板拒绝并报错，
而不是悄悄多出一条播放路径。

### 凭证只经钥匙串，且只进子进程环境

`ADR 0007` 写明「CLI 首版通过环境变量取得 API Key；未来 AppKit 使用 macOS Keychain。
配置文件只保存密钥引用，不保存明文密钥」。这里确认该条已实现，并补充两点：

- 变量名来自 `speech profile show --json` 的 `api_key_env`，不是 AppKit 硬编码的常量。
  配置文件和任何 receipt 都不回显密钥值，所以环境是唯一通道；
- 密钥**只注入子进程的环境，不进入 argv** —— 命令行参数对同机任意进程可见。
  并且该环境是**合并**进继承环境的，不是替换：替换会剥掉 `HOME` 和 `PATH`，而语音
  状态位于 `~/Library/Application Support/books-exporter/speech/`，那会表现成
  「profile 丢失」而非「启动方式错误」。

`profile` / `play` / `cache` / `history` 不需要凭证，因此不接收它。需要凭证的是
`speech voices`（免费但联网）和 `speech generate`（计费）。

### 面板即确认，不增加第二次确认

`ADR 0007` 写明「人类 CLI 在单条生成前显示内容类型、音色和估算字符数。明确执行生成
命令本身就是授权，不增加第二次确认」。AppKit 沿用同一条规则：费用提示与解析后的参数
就在「生成」按钮按下时可见，之后没有第二个弹窗。

费用提示**不得显示金额**。契约里没有货币、没有单价、没有总额，只有本地估算的计费
字符数和供应商回传的实际用量。显示任何金额都是编造。

### 改一个音调参数就是一次新的计费生成

`clip_id` 是「内容 + Voice Profile」的指纹。因此改变音色、语速、音量或声调中的任何
一个，得到的是**另一个 clip** 和**另一次计费**，而不是对同一段音频的重新渲染。

面板必须在参数与已缓存音频不同时说明这一点。把滑块当成「调音」而不说明它会重新
计费，是这个界面上最直接的收费意外来源。

### 不可用组合显示为不可用，不静默替换

`ADR 0007` 写明「不存在的音色、情感或风格组合必须显示为不可用，不能静默替换为近似
音色」。面板据此：

- 存储的音色不在当前目录中时，**不**退回到列表第一条，而是停在第一个**可用**项上
  等用户选择；
- 不可用的条目**留在列表里**并附带不可用的原因，而不是消失或被换成别的；
- 两级分组按 `voice_name` 进行 —— 这是契约提供的唯一分组键。供应商把情感和风格编码
  在 `voice_id` 变体里，契约里**没有**「基础音色 ID」字段，所以这是一层显示分组，
  不是供应商身份。类型注释里写明了这一点，以免被误读为身份保证。

### 只呈现已测试的渠道

设置页以只读声明呈现「SenseAudio — 已测试」，而不是供应商下拉选择。`ADR 0007` 说
SenseAudio 是「首个供应商」而非「已验证的唯一供应商」；给出选择器会暗示存在其他已经
跑通的选项。目录里来自未验证供应商的条目被**丢弃**而不是置灰 —— 置灰仍然是在承诺
一个存在但没走过的路径。

## 后果

- `ADR 0006` 的能力清单不含语音。本 ADR 填补该缺口：语音是 AppKit 的**第二个用户
  入口**，不是首期能力，也不是被保留在 CLI 的能力；
- Read-only TUI 和 Agent Data Skill **仍然没有**语音入口，与 `ADR 0007` 一致；
- `speech export` 于 2026-10-01（PR #63）接入，参数跟随 CLI 契约；导出目标
  **不是任意目录** —— 面板显示该书的导出根，没有记录时先引导用户导出本书 Markdown，
  规则见 [`ADR 0009`](0009-speech-export-target.md)；
- **（2026-10-02）AppKit 已覆盖「生成 + 播放 + 音色选择 + 导出 + 列出已有音频」。**
  面板读 `speech cache status` 回答「这条标注之前生成过吗」。这是遵守本 ADR 的
  「图形界面不得重实现语音语义」，而不是绕过它：`clip_id` 的指纹算法在 Rust 侧，
  界面要回答归属就只能问契约。三条由此确定的边界：

  - **`null` 归属不参与筛选。** `asset_id` / `annotation_id` / `content_kind` 在
    `corrupt` 时为 `null`，契约不回退到 state，界面同样不猜。归属不可信时把 entry
    归给某条标注，比不归属更危险：用户会播放并导出一段不属于自己的音频，而界面上
    没有任何东西提示这件事。
  - **界面不能预测缓存命中。** 缓存条目不携带音色与音调，而 `clip_id` 是它们的指纹，
    所以面板**无法**知道自己会算出哪个 ID。因此「会复用缓存」只能是条件句，
    不能是结论。原实现把当前选中的音调跟存储的 Voice Profile 相比后宣布
    「参数与已缓存音频一致」，而 Profile 不含文本——音调一致但文本不同就是另一条 clip。
  - **「当前这条 clip」必须与内容类型绑定。** 一条标注的高亮和笔记是两条独立 clip，
    切内容类型而不丢弃选择，会让导出作用于面板当前不显示的那一半。
- **（2026-10-01 更正）** 本 ADR 初版写的是「AppKit 的语音验证全部是 mock 的」
  「**AppKit 的端到端真实验收尚未执行**」。这两句已过期：同日用户在**打包后的 app**
  里对本机真实供应商跑通三次，本机
  `~/Library/Application Support/books-exporter/speech/attempts/` 留下三条
  `status: "succeeded"` 的 Speech Attempt，均带供应商 `trace_id` 与回传字符数
  （73 / 34 / 34），对应三条不同 clip。初版依据的 CLI 最小探针（2 个 unicode 字符）
  仍在，但那已不是唯一的真实调用证据。`ADR 0007` 关于「真实 provider 验收是显式
  opt-in smoke、不进普通 CI」的**约束不变**，变的只是这条验收已经人工执行过；
- Swift 侧的新增协议测试仍然只能覆盖请求构造与回执解释，无法证明供应商会接受某个请求。
  那一条只能由 opt-in smoke 覆盖 —— 上面那次人工验收正是这样做的，不在 CI 里。

## 非目标

- 本 ADR 不实现代码，也不改变 `ADR 0007` 已确立的供应商边界、缓存语义或失败路径；
- 本 ADR 不引入第二个语音 provider，也不把 `senseaudio` 写成永久唯一；
- 本 ADR 不在 AppKit 中重新实现目录缓存、音频校验或导出清单；
- 本 ADR 不授权 AppKit 批量生成。批量仍是 `ADR 0007` 的后续决策，且需要单独展示范围、
  片段数量和字符估算。
